# Judge’s report

**Verdict: passes the public benchmark and the submission interface, but fails the assignment’s core requirement to answer from the supplied snapshots.** I reproduced a **96.90% public score** and a **100% self-test score**. The decisive result was an evidence-change test. I changed the authoritative auto-loan APR to **9.87%** in an in-memory snapshot, then removed the page in the next snapshot. The system answered **5.39%** both times. It also returned the same 11 real-site conflicts before ingesting any pages.

I audited every submission module, the assignment and design documents, the scorer, the starter, the public questions and saved results, and the synthetic fixtures. I verified that the extracted snapshot files match all five supplied ZIPs byte for byte, loaded all **3,294 pages**, and checked source passages for the findings below. I ran the local harness with output captured in memory and bytecode writes disabled. The file inventory and content hash matched before and after the targeted tests. The hidden questions, hidden conflict gold, and organizer repository access were unavailable, so this report gives a readiness judgment rather than an official hidden score. Snapshot links refer to the files extracted from the supplied ZIPs. [Assignment](Knowledge-Hackathon-Assignment.pdf)

The highest-risk unscored combinations are **a historical cutoff plus an exact tier**, **a removed page plus a surviving stale promotion**, **a correct product with an unpublished field**, and **two valid facts that differ by rate type, product, or reporting period**. These follow directly from the rubric and can be tested using the existing five snapshots. As a judge, I would credit the interface, offline operation, speed, and reproducible public results. I would withhold acceptance on temporal accuracy, qualified retrieval, and conflict discovery until the answers and conflicts demonstrably change with the eligible evidence.
